## 0. 落地判定：三厂都能"不依赖厂商商店"自主部署（2026-10 一手调研）

> **结论：Agent 不是幻想。三家官方文档/官方仓库都给了"脱离厂商商店、自己把程序装上去"的路径——靠 SSH + 容器/脚本。** 唯一绕不开厂商的是**底层电机/固件**（物理必然）。

| 维度 | 宇树（EDU/开发版） | 智元 | 众擎 |
|---|---|---|---|
| **能否自主部署** | ✅ EDU 可（基础版禁用 SSH） | ✅ 可 | ✅ 可 |
| **SSH** | `unitree@192.168.123.164`（默认 `123`） | `agi@` 带 sudo | `ubuntu@.162`/`user@.163`（弱口令） |
| **侧载方式** | curl\|bash / pip / git / `docker load` | rsync/scp + Docker/podman 容器 | `install.sh` = SSH+rsync |
| **实证案例** | dimOS、WendyOS(wendy-agent)、LeRobot、unitree_rl_gym | 官方"部署"文档即此路径 | 官方 ROS2/native SDK 仓 |
| **出站连接** | ✅ 连 WiFi → 外连自建服务器 | ✅ | ✅（局域网内网 192.168.0.0/24） |
| **下发是否需厂商云** | 不需要 | **不需要**——资源 RPC 是本地 HTTP（`10.42.10.10:51049`），**不过 OMP 云**（云仅埋点） | **本就无云**，只能本地网 |
| **执行是否绕不开厂商** | ❌ 必用 SDK2/DDS | ❌ 必用 AimDK RPC/ROS2 | ❌ 必用 ROS2/Native SDK |
| **硬约束** | 基础版禁 SSH；改装/开发者模式损坏**失保**；EULA 禁"用非授权第三方软件接入其**云服务**" | 禁跑 x86 运控板、宿主机禁 apt（容器内允许）——**是保修条款非技术锁** | 弱口令、**无云 OTA**、IP/凭据对 T800 不通用 |
| **商店开放** | **UniStore 第三方通道已开放**（2026-05） | 无付费商店（开放平台） | 无商店 |

**两条关键红线（必须守）**
1. **只做本地技能下发，不接入/篡改厂商云服务**——宇树 EULA 明确禁止"用非授权第三方软件接入其服务"。
2. **改密/加固**——三家默认弱口令（宇树 `123`、众擎 `ubuntu/ubuntu`），Agent 首次运行**必须强制改密 + 自建 mTLS**，否则是重大安全漏洞（宇树 Go2 已有 root RCE 的 CVE）。

**三通道落地对照（对应你的三通道设计）**
| 你的通道 | 落地方式 | 依赖 | 状态 |
|---|---|---|---|
| **一键厂家接口下发** | 宇树走 **UniStore 开发者通道**（已开放）；智元/众擎暂无云商店 | 厂商合作/审核 | 宇树 ✅、其余待建 |
| **平台 agent 下发** | **SSH + 出站 agent + 容器化技能**（三家 EDU/开发版均可） | 设备开放 + 网络可达 | ✅ 可行 |
| **纯手动下发** | 下载 + 人工安装 | 无 | ✅ v1 已跑通 |

## 1. 目标与范围

**Agent 要做什么**：常驻/接入机器人，接收平台下发的技能指令（安装/卸载/启停/回退/回收），执行并回报状态；执行前校验平台签名与本人授权。

**目标机型（P0，只这三家最新主流）**
| 厂家 | 机型 |
|---|---|
| 宇树 | G1（**首选**）、H1/H2、Go2/B2 |
| 智元 | 远征 A2（旗舰/青春）、A3-Ultra、灵犀 X2 |
| 众擎 | PM01、T800 |

**不做（P0）**：特斯拉/Figure/Atlas 等无公开 SDK 的机型（L3 仅展示）；其余品牌 P1 再评估。

## 2. 三家适配差异（核心难点）

> 三家"技能下发载体"**根本不同**——Agent 必须做**三套形态**，不能一套通吃。

| 维度 | 宇树 | 智元 | 众擎 |
|---|---|---|---|
| **下发模型** | **容器应用级** | **资源级** | **插件级** |
| 通道 | 打包 Docker(ARM64) 应用 → 传 UniStore（或厂商云） | 放 `tmp` 目录 → RPC 同步 → 持久化 `custom/default` | 注册为 Native SDK 的 **Runner 插件** → `install.sh` 部署 |
| 技能形态 | Docker 应用（含 `metadata.yaml`，80 端口 HTTP） | 资源文件（mcap/动作/表情/音频） | 控制算法/状态插件 |
| 通信 | **DDS(CycloneDDS)** via SDK2 | **HTTP JSON RPC + ROS2 Topic**（AimRT/AimDK） | **ROS2 Humble + CycloneDDS**（`ROS_DOMAIN_ID=69`） |
| 算力 | ARM64(Orin 级) 主控 | x86(运控，**禁二开**) + Orin(应用) | Jetson Orin NX(应用) + Intel N97(运控) |
| 硬约束 | 守 FSM：Passive→执行→**交还官方运控** | **禁跑 x86、禁 apt、轮询 ≤0.2Hz**（违反不保修） | 交叉编译 aarch64 |
| OTA | 云 OTA（应用下载） | **机上有 `ota_master/slave/gateway`**（最完整） | 未找到公开 OTA |
| 开放度 | **最高（唯一有官方 App Store + 打包模板）** | 中高（接口全开、约束硬） | 高（SDK/仿真全开） |

**结论**
1. **先做宇树 G1**——唯一有官方 App Store + 完整打包模板 + 现成 DDS 控制流，起步最快。
2. **智元的 Agent 必须装在 Orin 侧**（x86 运控板禁放二开，抢资源会摔机）。
3. 通吃的抽象层 = 统一 ① **ARM64 构建产物** ② **ROS2 话题**（三家都支持，但宇树主通道是 DDS、智元高层在 HTTP RPC，ROS2 只覆盖部分）③ 技能的三种表达形态。

## 3. Agent 架构（插件化）

```
┌──────────────── Agent 核心（三厂通用） ─────────────────┐
│ ① 注册/配对：首联 → 换 DID + MQTT 凭证（或厂商云凭证）    │
│ ② 心跳：MQTT keepalive + 遗嘱 → 在线态                   │
│ ③ 指令校验：RSA 验签(task_id+skill_id+version+hash+ts)   │
│    + ts 窗口(±5min) + **按 task_id 幂等去重**（MQTT QoS1）│
│ ④ 授权校验：执行前校验本人 entitlement（防试用回收被绕）   │
│ ⑤ 受控执行：限幅/限速/急停/`max_duration_s` 超时交还      │
│ ⑥ 回报：phase(downloading/installing/done/failed/进度)   │
└───────────────────────┬─────────────────────────────────┘
                        │ vendor 插件（一厂一个）
     ┌──────────────────┼──────────────────┐
     ▼                  ▼                  ▼
 宇树插件            智元插件            众擎插件
 (Docker应用/        (资源+RPC/          (Runner插件/
  UniStore/DDS)      AimDK/OTA)         ROS2/CycloneDDS)
```

**为什么插件化**：三家下发载体不同（§2），核心协议一致、载体各异 → 一厂一插件，核心零改动。

## 3.5 Agent 功能明细（落地清单，照搬成熟 IoT 范式）

> 参考 balena/Mender/Greengrass/Azure IoT Edge 的通行做法：**出站连接 + 设备侧常驻 agent + 声明式目标状态 + 容器化负载 + 签名工件 + mTLS + A/B 回滚**。

### F1 · Agent 核心（三厂通用）

| 模块 | 功能 | 细节 |
|---|---|---|
| **引导装机（Bootstrap）** | 一次性把 Agent 弄上机器人 | 用户按引导在机器人上执行一条命令（SSH）：`curl -fsSL https://<平台>/agent/install.sh \| bash --token <一次性码>`；**或**厂商通道（宇树 UniStore / 厂商预装）。**这是唯一的"手动一步"，之后全自动** |
| **出站连接** | Agent 主动连平台，**不需要机器人有公网 IP** | MQTT(8883)/WebSocket over TLS；断线重连 + 指数退避。设备常在 NAT/客户内网后，**出站是唯一现实架构** |
| **设备身份** | 一机一证 | 首启用**引导证书/一次性码**换**唯一设备证书**（X.509）；后续 mTLS 鉴权（学 AWS Fleet Provisioning / balena provisioning key） |
| **声明式目标状态** | Agent 只对齐"期望状态" | 平台下发"这台机器应有技能集合 {A@v2, B@v1}"；Agent 拉取→diff→执行→上报，**不做命令式逐条** |
| **指令校验** | 防伪造/重放 | RSA/Ed25519 验签（`task_id+skill_id+version+hash+ts`）+ ts 窗口 ±5min + **按 task_id 幂等去重** |
| **授权校验** | 防试用回收被绕 | 技能启动时校验本人 entitlement（本地缓存 + 定期回源） |
| **健康上报** | 在线态 + 诊断 | 心跳（MQTT keepalive + 遗嘱）；技能运行状态、资源占用、错误码 |
| **自更新** | Agent 自身可升级 | Agent 与技能负载**解耦**（学 balena supervisor）；Agent 升级失败自动回滚旧版 |

### F2 · 技能形态与部署（vendor 插件）

| 厂家 | 技能打包 | 部署动作 |
|---|---|---|
| 宇树 | **Docker 应用包**（`app/` + `metadata.yaml`，ARM64） | `docker load` + 起容器（对齐 UniStore 规范，**同一包既能进 UniStore 也能本地部署**） |
| 智元 | **资源包**（mcap/动作/表情） | 拷进 `/agibot/data/resources/tmp` → RPC 触发同步 |
| 众擎 | **Runner 插件 / ROS2 节点** | `rsync` 到机上 → 机上编译/运行（对齐 `install.sh` 模式） |

### F3 · 签名与回滚（安全底线）

- **技能包签名**：平台私钥签，Agent 内置公钥验签；**能做 TUF/Uptane 就做**（防降级/防回滚）。机器人的权威候选标准是 **Uptane（TUF 的汽车扩展，已有 Uptane++ 用于自主系统）**。
- **回滚**：技能版本化；启动失败/超时→**自动回滚上一可用版本**；底层若涉固件才需要 A/B 分区。
- **默认拒绝 + 单次授权**：高危技能"**执行这一次、在这次授权下**"（学 ganglion 的签名 WASM 思路）——特别适合"试用"场景。

### F4 · 安全加固（必须做，不能省）

- ⚠ **三家默认弱口令**（宇树 `123`、众擎 `ubuntu/ubuntu`）→ Agent 首次运行**强制改密 + 禁 root 直登 + 只开必要端口**。
- **不接入/篡改厂商云服务**（宇树 EULA 红线）——Agent **只做本地技能下发**，不碰厂商云账号体系。
- **一机一证 + mTLS**；平台侧对每个 agent 单独授权，泄露可单独吊销。

### F5 · 通道选择逻辑（平台侧）

用户点"下发"时，平台按 **技能声明的通道 ∩ 设备能力 ∩ 设备在线状态** 自动选：
1. **厂家接口通道**可用（如宇树 UniStore 已授权）→ 优先（最省事）
2. 否则**平台 agent 通道**可用（设备已装 agent 且在线）→ 用
3. 都不行 → **纯手动通道**（下载 + 图文引导 + 自报）

## 4. Agent 协议 v1（与平台约定）

| 类别 | 内容 |
|---|---|
| 下行指令 | `{task_id, operation(安装/卸载/回滚/启用/停用/回收), skill_id, version, package_url, package_hash, signature, ts}` |
| 上行回报 | `{task_id, phase, progress, error_code, ts}` |
| 签名 | `RSA_Sign(平台私钥, task_id+skill_id+version+package_hash+ts)`；Agent 内置公钥验签；**ts 窗口 + task_id 幂等**（应对 MQTT QoS1 的重复/乱序） |
| 错误码 | 沿用平台侧 `DEP_001~009`；新增 `TRIAL_001/002` |

**⚠ 协议不定死"下发方式"**——下发方式由 vendor 插件决定（宇树=容器上传、智元=RPC 同步、众擎=插件部署）。

## 5. 约束与安全（各家硬约束，必须遵守）

| 约束 | 适用 | 违反后果 |
|---|---|---|
| 二开程序**禁跑 x86 运控板** | 智元 | **摔机**、不保修 |
| **禁 apt**（不得装系统软件） | 智元 | 不保修 |
| RPC 轮询状态 **≤0.2Hz** | 智元 | 不保修 |
| 执行完**交还官方运控**（FSM 回落） | 宇树 | 失控 |
| 交叉编译 **aarch64** | 众擎/宇树 | 二进制跑不起来 |
| 技能启动时**校验授权** | 全 | 试用回收被拔线绕过 |

## 8. 里程碑（与平台侧并行）

| 里程碑 | 内容 | 依赖 |
|---|---|---|
| A1 | Agent 核心（注册/心跳/验签/幂等/回报）+ **宇树插件** | 平台 register/心跳接口 |
| A2 | 智元插件（资源+RPC+OTA 适配，守硬约束） | 智元 AimDK 版本 |
| A3 | 众擎插件（Runner + ROS2） | 众擎 SDK |
| A4 | 受控执行（限幅/急停/超时交还）+ 授权校验 | — |
| A5 | 三厂真机联调 → **平台 W4 可启动** | A1–A4 |

**关键依赖**：**A5 完成 = 平台侧 W4（下发链路）的触发条件**。在 A5 之前，平台只能走 manual 通道。

## 9. 风险

| 风险 | 等级 | 应对 |
|---|---|---|
| 三厂 SDK/固件**版本演进**（智元按 AimDK 版本发版，有不兼容变更） | 高 | Agent 按版本适配 + 灰度；`device_model.min_agent_version` 卡住旧版 |
| 智元硬约束违反 → 不保修 | 高 | Agent 严格：不装 x86、不用 apt、低频轮询 |
| 宇树 UniStore 是否**开放第三方上传**（现多为官方） | 中 | 备选走厂商云 API / 人工；确认 UniStore 开放政策 |
| 众擎无公开 OTA | 中 | 走 `install.sh` 真机部署；OTA 待厂商 |
| Agent 与平台**版本不匹配** | 中 | 协议版本号 + 兼容矩阵 |
