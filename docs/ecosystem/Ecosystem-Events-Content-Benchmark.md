# 赛事活动与动态资讯：官方实践研究及验收建议

> 文档状态：研究底稿（2026-10-18）。用于记录官方平台调研、工程边界与验收思路的来源依据。
> 正式实施方案以 [产品技术方案](Ecosystem-Events-Content-Plan.md) 和 [工程任务及验收矩阵](Ecosystem-Engineering-Backlog.md) 为准；
> 来源事实与版权口径以 [官方实践研究](Ecosystem-Official-References.md) 为准。三份正式文档吸收并细化了本文的建议，若表述冲突以正式文档为准。

研究日期：2026-10-18（Asia/Shanghai）。用途：为 summon-mecha 下一阶段工程规划提供依据，未开发功能、未跑写库测试、未联系外部机构。下文“来源事实”与“项目建议”分开；建议不代表外部赛事规则，也不代表本项目已有对应表或 API。

建议先建设可信的活动记录、报名和内容发布流程。赛季、赛项、场次、规则和成绩需要能追溯；资讯需要能说明是谁发布、依据什么来源、何时更正或撤回。优先复用现有 Laravel 模块、管理权限、审核、审计和消息能力，先盘点现状再决定增量。首期不纳入真钱票务结算、全球联赛编排、自动裁判、独立团队 RBAC、未经许可的内容抓取或转载。

## 三、适合当前项目的最小工程边界（建议）

### 1. 活动、赛事和报名

- 先盘点现有赛事、报名、作品、奖项、动态和审核接口，再做字段及状态缺口清单。以下是逻辑概念，不要求每个概念立刻新建一张表。
- 普通活动记录类型、主办方、场地/线上地址、时区、公开与报名时间、起止时间、状态和来源。系列赛事按需关联赛季、赛项、站次；赛程场次与活动展示页分离。
- 可复用的队伍身份与当届报名分离；报名保存队伍/个人、提交者、成员与资格快照、规则版本、审核结果。首期采用现有账号及管理员权限，不因此扩张独立团队 RBAC。报名表只收必要信息，公开队伍信息与私有联络资料分开。
- 规则记录版本号、适用赛季/赛项、生效时间、来源、权威语言、变更摘要。自有或获准存储文件可保存哈希和历史版本；仅获准外链的资料不能偷偷缓存全文。重大修改是否要求重新确认，应在本届规则中先确定。
- 活动发布流程可为草稿→待审→已发布→归档；举办状态独立表达计划、延期、改期、取消、结束。报名接受状态以服务器时间和当前活动状态为准，不能仅依赖前端按钮或缓存。
- 报名幂等与名额原子变更必须一起设计：唯一约束防重复、事务重新校验状态与容量；拒绝和回滚不消耗名额。候补、退队补位及一校多队额度待实际政策明确再加入。
- 外部活动可先做经过核验的目录加官方报名外链，必须显著标注外部主办/外部报名；不得误呈现为平台代报名成功。

### 2. 赛程、成绩、申诉和奖项

- 首期允许人工录入或 CSV 预览导入赛程/成绩：校验场次、参赛单位、分数格式和引用，再生成草稿，由有权限的人发布。排名算法和同分政策未确定时只发布核准成绩，不自动生成“官方排名”。
- 每次已发布成绩修订保留操作者、原因、前后版本、关联申诉和裁决；旧版本不继续冒充当前结论。受影响排名、奖项和作品展示要么按同一版本更新，要么明确显示待复核。
- 申诉关联当届规则、场次或成绩版本；提交资格、截止时间、附件类型和裁决者配置来自本届规则。受理、审查、裁决、通知留痕。赛前咨询、赛后申诉、一般举报采用不同类别，避免公开讨论区变成裁决入口。
- 奖项说明主办方、评审方式和公布状态，获奖名单与奖金支付分开；本轮不引入奖金支付、票务退款、平台抽佣或提现结算。

### 3. 动态资讯和内容治理

- 采用标题、摘要、正文/官方外链、封面、分类、关联活动、作者、发布机构、来源类型、原作者、原文 URL、原文发布时间、平台发布时间、修改时间、权利依据、审核人和版本等信息。必填项按内容类型定义，不能用伪造作者填空。
- 流程建议为草稿→待审→已批准/定时→已发布；独立保留正常、暂缓、撤稿处置状态。审核后修改正文、来源或附件应使原审批失效或重新走明确的变更审批，避免绕过审核。
- 可恢复的暂缓与终态撤稿分开。撤稿后列表、详情、搜索、推荐、分享摘要、历史版本公开 API、缓存和定时任务均不得继续输出撤稿正文或附件；保留必要的中性撤稿说明。受限审计只按权利、隐私与留存规则保存必要证据，不能默认永久保留和公开所有旧正文。
- 事实更正展示更正说明、时间和责任编辑；首次发布时间不因普通修改而刷新。源站撤稿、链接失效或授权到期应进入人工复核，不能通过重新抓取覆盖本地裁定。
- 富文本使用允许列表清洗；封面和附件验证类型、体积、存储权限。默认不由服务器任意抓取用户提交 URL，减少 SSRF 和未经授权复制。作者资料、报名资料、审核备注不得被通用内容序列化接口带出。
- 定时发布、改期通知和撤稿传播使用提交后入队、幂等键和当前状态复核；首次可只用站内消息。是否启用邮件、短信或对外分发是独立运营选择，本研究未发送任何消息。

## 四、测试、运营与安全验收矩阵（未来实施的验收建议，均未在本轮执行）

| 范围 | 关键验证方式 | 可验收结果 / 运营证据 |
| --- | --- | --- |
| 模型复用与迁移 | 清点现有路由、表、状态、权限及存量数据；在独立库演练升级/回滚 | 不重复造功能；历史报名、作品和内容关联不丢；迁移与回滚步骤可审阅 |
| 赛季与规则 | 同队跨赛季报名；接受 V1 后发布 V2；修改同 URL 文件的来源版本 | 历史快照不被覆盖；新报名接受正确版本；重大变更按已定政策再确认 |
| 报名并发 | MySQL 两连接/多进程争最后一个名额、重复提交、审核与取消竞争 | 不超额、不重复；拒绝不计数；回滚不留半个报名；真实锁等待和清理结果可核验 |
| 时间与活动状态 | 截止点前后、UTC/展示时区、定时任务延迟；取消/延期与报名并发 | 服务器统一判定；取消后不能报名；待定延期不显示虚构日期；已报名人可见变更说明 |
| 权限与个人信息 | 其他用户/队伍枚举报名、附件、申诉 ID；前台/后台导出权限 | 未授权访问被拒；公开名单不泄露手机号等私有字段；导出留痕并防 CSV 公式注入 |
| 赛程及成绩导入 | 错场次、重复单位、非法分数、跨赛项引用、重复导入和恶意 CSV | 导入先预览、错误定位；未审核草稿不公开；重试不重复或覆盖已终审结果 |
| 成绩修订与申诉 | 两个编辑竞争修订；过期申诉、越权裁决、证据类型不符 | 防止静默覆盖；有效版本唯一；拒绝有明确原因；裁决与排名/奖项版本可追溯 |
| 资讯来源与版权 | 缺作者、来源不明、仅外链许可、授权到期、商业供稿 | 必要字段和权利依据齐全才能发布；来源及合作标签可见；没有默认全文搬运 |
| 审核绕过 | 待审直接调用发布 API；批准后换正文/文件；跨管理员权限 | 状态及权限在服务端重新验证；内容变化不会沿用不相符的审批 |
| 更正和撤稿 | 更正前后日期；撤稿与定时/重试并发；直接访问附件与历史 API | 更正可见且首发时间不变；撤稿不被任务复活；所有公开路径无正文/受撤附件泄露 |
| 内容与文件安全 | 脚本、危险链接、伪造 MIME、超大文件、路径穿越、内网 URL | 清洗/拒绝符合策略；私有文件不直接公开；日志不含令牌与报名敏感资料 |
| 队列与缓存 | 提交/回滚后的定时任务；重复投递、失败重试、撤稿后缓存失效 | 事务未提交不发布；失败可重试但不重复通知、不恢复终态；异常可定位及人工处理 |
| 前台体验 | 未发布/空列表、分页、筛选、已满/待审/延期/取消、移动窄屏 | 时间、报名状态和来源清晰；错误提示可操作；不显示虚假参与人数或占位获奖信息 |
| 赛前运营 | 明确主办归属、规则版本、场地与安全说明、评审/裁决负责人、变更预案 | 发布清单由负责人确认；第三方活动状态标记核验时间；未确定政策不以工程默认值冒充 |
| 赛中与赛后运营 | 演练成绩暂停确认、人工裁决、批量更正、取消通知及紧急撤稿 | 有责任人、处理记录和人工兜底；终审/获奖公布可复核；异常任务不长期无人处理 |

验收证明应分层报告：普通单元/接口测试、真实 MySQL 并发、队列进程、浏览器体验分别记录。不得把控制器调用称为 HTTP 吞吐压测，也不得把模拟赛务测试称为真实赛事或机器人现场安全验收。未来测试继续使用隔离数据库和带 run_id 的夹具；不能借用商城主库执行写入探针。

## 五、分期和待明确事项（建议）

1. **现状与业务确认**：映射已有活动/赛事/动态能力，确定平台是自办、合作承办还是外部目录；确认公开内容类型、转载权利、资格适用和个人信息范围；输出接口/状态/数据差距表。
2. **首期可运营闭环**：自有或授权活动发布、来源可追溯、免费/意向报名、审核、规则快照、状态变更、基础运营审计；资讯的审核、署名、更正、暂缓/撤稿同步完成。已有能力优先修补一致性和测试，不重复建设。
3. **首场实际赛事驱动**：仅在参赛规则确定后加入赛程、人工核准成绩、申诉及奖项版本。容量/候补、赛队资格、申诉时限、证据规则、裁决权限必须有运营明确结论。
4. **后续按需求扩展**：可信官方接口接入、公开 Web 的结构化数据、复杂赛制与排名另行立项；不因对标头部平台就默认需要微服务、实时计分硬件或跨国财务体系。

需要业务负责人拍板的最少问题：首期谁主办；个人还是队伍报名；名额、退队和候补政策；谁确认成绩及裁决、什么材料可申诉；资讯是原创/机构供稿/获准转载/外链摘要中的哪些；各类内容与报名资料保留多久。工程人员可先给出选项及影响，不能自行发明这些业务规则。

本研究核查的是公开官方页面和指定归档资料，未访问任何机构后台，未证明外部系统的具体锁实现、完整内容审核制度或本项目已满足全部法规。未完整读取 RoboMaster 当前全部规则 PDF，因此不提供其最新规则版本号、申诉分钟数或罚则作为本项目默认值。
