# 技能质量体系与过审门槛（好/一般并存 · 垃圾不过审）

> 日期：2026-10-13 ｜ 原则：**好技能与一般技能并存 = 正常市场；垃圾技能不是"质量差"，是"不合格"，必须在审核阶段拒掉。**
> 配套：[skill-standardization-chain.md](./skill-standardization-chain.md)（转换层）、[skill-supply-plan.md](./skill-supply-plan.md) §4.8 审核

---

## 0. 一条清晰的线：过审 ≠ 优质

```
        不合格（垃圾） │ 及格线 │  合格（可上架，内部再分级）
  ─────────────────────┼────────┼─────────────────────────────►
   ❌ 审核拒绝，不进市场  │ 客观可测 │  ★合格  ★★优质  ★★★精选
   （能用都用不了/不安全/违规）│ 的能用+安全+合规 │  （好/一般并存，市场检验）
```

- **及格线（过审）** = **能用 + 安全 + 合规**——**客观可测，不靠审美**。
- **及格以上的好坏** = 交给**质量分级 + 用户评分 + 数据**——**这才是市场**。
- **及格线以下** = **拒**，这是"垃圾不能过审"。

> 核心：**平台用客观标准守住及格线；及格线以上让市场分好坏。** 不越界去当"审美裁判"，但也绝不放垃圾进来。

---

## 1. "垃圾/不合格"的定义（**拒绝清单**，可客观判定）

### A. 技术不可用（**可全自动判**）
| 项 | 判据 |
|---|---|
| 包格式不合格 / manifest 缺项 | schema 校验不通过 |
| 动作数据损坏 / 跑不起来 | **仿真预跑：加载即报错** |
| **机器人执行即摔倒 / 超时 / 崩溃** | **仿真跑分：跑不完 / 姿态失稳 / 超时** |
| 权限越界 | 声明 `permissions` 与实际调用不符 |
| 文件超限 / 命中黑名单 | 大小/扩展名校验 |

### B. 内容与合规（**自动 + 人工**）
| 项 | 判据 |
|---|---|
| 涉政涉黄/违规内容 | 内容安全检测（`msgSecCheck`+多媒体） |
| 恶意代码 | 静态扫描三层 |
| **侵权**（盗用他人动作/素材） | 无授权声明 / 举报核实 |
| **描述与内容不符**（虚假宣传） | 人工核对 |

### C. 功能不完整（**人工**）
| 项 | 判据 |
|---|---|
| 半成品（缺关键文件、不能独立运行） | 人工/仿真 |
| 人工通道技能无安装说明 | `install_guide` 为空 |

### D. 物理安全（**自动 + 人工**）
| 项 | 判据 |
|---|---|
| **高危动作无 `safety` 声明** | `manifest.safety` 缺项 |
| 会自伤/伤人的动作未做限制 | 无 `requires_open_area`/`estop`/`max_duration` |

> **关键**：A 类（技术不可用）**可全自动判**——尤其"**仿真跑不起来**"是客观的垃圾过滤器，不依赖人工审美。**这是把"垃圾挡在门外"的主力。**

## 2. 三层审核（对准入线）

```
① 机器自动审  →  ② 仿真预跑  →  ③ 人工审核  →  过审 / 拒绝
   (格式/安全/权限/内容)  (能不能跑、稳不稳)  (完整性/一致性/侵权)
```

| 层 | 谁 | 判什么 | 不过 → |
|---|---|---|---|
| **L0 机审** | 系统 | 格式、权限越界、黑名单、内容安全、恶意代码 | **拒绝** |
| **L1 仿真预跑** | 系统 | **动作能不能跑起来、稳不稳、超时否** | **跑不起来 → 拒绝**；能跑但分低 → **降级**（不放精选） |
| **L2 人审** | 审核员 | 功能完整性、描述与内容一致、侵权 | **拒绝** |

> **L1 仿真预跑是"垃圾过滤器"**——客观、可批量、不靠人。**建议 P0 就上**（对齐智元 Genie Sim / 宇树 mujoco 做法）。

---

## 3. 质量分级（过审**之后**的好/一般）

> 及格线以上，**不拒绝**，只**分级 + 排序**——这才是"好/一般并存"的市场。

| 等级 | 判据（示例） | 权益 |
|---|---|---|
| ★★★ **精选/官方认证** | 仿真高分 + 用户评分 ≥4.5 + 安装成功率 ≥95% + 人工复核 | 首页推荐、优先展示、"认证"标 |
| ★★ **优质** | 评分 ≥4.0 + 成功率 ≥90% | 正常展示 |
| ★ **合格** | 过审即可 | 正常展示，无额外加权 |
| （不合格） | 未过审 | **不上架**（已在审核拒掉） |

**降级规则**：上架后若**安装成功率骤降 / 大量差评 / 出现事故** → 自动降级 + 进复审（联动 §4.19 熔断）。

## 4. 质量分从哪来（客观，不靠感觉）

| 来源 | 采集方式 | 用途 |
|---|---|---|
| **仿真跑分** | 上架前仿真预跑（动作完成度/稳定性/超时） | 客观质量基线 + 拒垃圾 |
| **安装成功率** | `deploy_task` / `install_record` 聚合 | 真实可用性 |
| **用户评分/晒单** | `skill_review` | 市场检验 |
| **卸载率** | `install_record` | 留存 |
| **开发者等级** | 历史技能表现 | 分级 + 加权 |

## 7. 一句话原则

> **平台守住"及格线"（能用+安全+合规，客观可判、仿真跑分把关），把垃圾挡在门外；及格线以上的"好与一般"交给质量分级和市场——既不越界当审美裁判，也绝不放垃圾进来。**
