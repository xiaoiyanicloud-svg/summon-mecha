# 团队对 12 条反馈的回应与行动（Boss 决议 → 团队执行）

> 日期：2026-10-13 ｜ 场景：Boss 就 [团队评审](./skill-plan-team-review-2026-10.md) 的 12 个问题给出指示，团队逐条落地
> 范围收紧：**只做技能供需板块**（前端其余：首页/机器人库/租赁/方案，不动）

---

## 1｜商业模型未验证 →「先做标准融资」

**团队判断**：融资方向对，但**投资人尽调会问的还是同一个问题**——"有没有人付费"。标准融资的叙事必须把"验证"写进里程碑，否则尽调阶段会被同一处击穿。

**行动**
- 出**融资叙事**：市场（机器人装机量+TAM 估算）／痛点（有机器人却不会用）／差异化（跨品牌交付 + 导入器 + 合规先行）／里程碑／风险对冲。
- 把**「付费意愿实验」设为 A 轮前置里程碑**（最低成本去风险，见团队评审 §4）：2–3 个自营技能 → 小范围加价售卖 → 拿数据。**投资人喜欢"你用很少的钱证明了什么"。**
- 出**财务模型**：单位经济、成本结构、何时打平（团队评审财务视角已给框架）。

> ⚠ 团队保留意见：融资能解决"钱"，解决不了"有没有人买"。**建议把验证实验放在融资故事里，而不是等融资到账再想。**

## 2｜Agent 在开发中 →「适配宇树/智元/众擎最新主流机型」

**团队判断**：这是**把"通道=0"变成"通道在建"的关键好消息**——计划里最致命的问题被这条解掉了大半。但要注意：**三家下发方式不一样**（宇树=Docker 容器接管 DDS、智元=本体本地资源包 RPC 同步、众擎=开源 SDK），**Agent 要分别适配，不是一套通吃**。

**行动**
- 把 `device_model` P0 范围**收敛为"宇树/智元/众擎最新主流机型"**，其余品牌一律 **L3 仅展示**（符合 §0.5 兼容性分级）。
- Agent 按**厂商插件**架构（`vendor/` 目录已设计），一厂一插件。
- 等 [机型与 Agent 适配调研] 回来，补三家的 **SDK／下发接口／算力架构／固件门槛** 到计划。
- 触发条件更新：原"等有真机愿装 Agent"→ 改为"**Agent 支持三家主流机型后，`agent` 通道升级为 P0**"。

## 3｜全球是目标，短期「只做中国和美国」

**团队行动**
- §11 收敛为**双区域**：中国（微信/支付宝）+ 美国（Stripe/PayPal）。
- **两套法务主体**（美国需本地实体收 Stripe；中国走微信）。
- 合规清单**分中国/美国两栏**。
- 数据：美国用户数据按美国合规存/处理；**敏感生物特征数据不出境**（硬约束）。

## 4｜「合规清单」

**团队交付《合规清单》**（分三栏）：

| 区域 | 事项 | 是否阻断 | 周期 |

| **中国** | ICP 备案（门户+H5）、小程序 ICP 备案 | 阻断 | 10–20 工作日 |

| | **EDI/增值电信许可**（交易撮合+抽成） | 阻断（第三方交易） | 月级 |

| | 隐私政策/个保法、数据出境判定 | 阻断 | — |

## 5｜第三人责任 →「用户承担 + 平台卖保险」

**团队判断**：方向可执行，但法律上要写对——**平台不能靠格式条款完全免责**（《民法典》496–497）；且**自营时平台=销售者（无过错责任）**，仍需担。

**行动（需律师定稿）**
- 用户协议加**"机器人操作者责任条款"**：用户作为操作者，对操作造成的第三方损害承担责任（自甘风险 + 责任转移）。
- **平台提供保险购买入口**：高风险技能 **强制投保方可上架/使用**；保险单接入 `incident.insurance_claim` 闭环。
- 平台作为"网络交易平台服务提供者"（对齐《电子商务法》第38条）明确角色边界。
- 保留团队意见：**保险是关键兜底，但它兜的是钱，兜不了"平台被认定责任主体"** → 仍需产品检测+仿真预跑+熔断。

## 6｜「优化」（去过度设计）

**团队交付 MVP 收缩**（P0 只留技能供需主线）：

| 分类 | 内容 |
|---|---|
| **P0 必建**（≈10 张新表） | `device_model`、`device_binding`、`deploy_task`、`install_record`、`audit_record`、`security_scan`、`skill_category/tag`、`skill_search_index`、`notification`、`after_sale` |
| **P1** | 工单、对账、发票、开发者门户、熔断、事故闭环、结算提现 |
| **条件触发**（移出 P0） | EMQX/Go 全链路（等 Agent 就绪）、厂商 API 适配器、灰度/回滚、责任保险 |
| **暂不现实** | 训练/数据集平台、真·一步全球 |

> **原则**：禁止把"条件触发/暂不现实"当 P0 排期（§0.5 现实性分级）。

## 7｜「优化」（对齐行业单向）

**行动**：① 明确"**可导入 + 可导出**"，但只承诺 **L2 重定向**，不承诺跨本体开箱即用；② manifest 语言码用 **`en`** 对齐 Bagisto；③ 跨本体能力列为长期，不作卖点。

## 8｜前端「已有基本交互，聚焦技能供需」

**团队行动**：范围收敛——**只动技能相关页**（技能市场/详情/我的技能/我的设备/下发进度·结果/评价/售后/工单/通知/开发者门户 web-view 轻量视图）。**首页/机器人库/租赁/方案不动。**

## 9｜内容生态「你可以给建议」

**团队建议（按"现有客户能否付费"排序）**
1. **暖场/展演动作包（先做深）**：迎宾/招手/舞蹈/武术/合影 pose——被批评"肤浅"但**是硬件天花板下唯一能可靠交付、能卖钱的**。
2. **接待/导览/讲解**：技能 + 已有 AI 召唤/ASR/TTS 打包，给展厅/政务/文旅——**别人没有、你有**。
3. **直播/短视频互动**。
4. **企业定制编排**（毛利最高）。
5. **生产力类（谨慎）**：只做展示/咨询，**不承诺可交付**（硬件不支持）。

## 10｜兼容性数据「你可以调研数据」

**行动**：机型库种子数据调研**进行中**（宇树/智元/众擎/乐聚/傅利叶/优必选 + 海外代表），采集 自由度/算力/接口/固件/开放程度。**结论会标注"哪些机型规格公开可查、哪些几乎查不到"**——这决定兼容性校验数据能采多全。

## 11｜Coze 是「平台调度智能大脑，面向 C/B 端交互」

**团队修正之前判断**：Coze 不再是"开发栈风险"，而是**平台调度智能大脑**（小召 / ASR / TTS / 内容理解 / 审核辅助）。

**行动**
- 改计划对 Coze 的描述：**核心调度层**，非临时依赖。
- 但仍加**抽象层**：Coze 能力接口化，**架构上可替换**（避免单点锁定）——这是工程惯例，不影响 Coze 是主脑。

## 12｜「优化」（漏洞）

**行动（实现注意事项）**
- **试用回收被拔线绕过**：加"技能启动时 Agent 校验授权"（原 P1 → 与试用同期）。
- **静态扫描误报**：WARN 不拦截、进人工复审、规则热更新。
- **灰度缺失前无护栏**：熔断 kill switch 与 Agent 通道同期上线。
- 促销/试用**多账号刷**：设备指纹 + 手机号去重。

## 汇总：本轮后计划的三处实质变化

1. **通道从"=0"变"在建"** → `device_model` 收敛为宇树/智元/众擎，Agent 分厂商插件。
2. **全球从"幻觉"变"中国+美国"** → 双区域、双主体、双支付、合规清单分栏。
3. **规模从"过度"变"MVP"** → P0 砍到 ≈10 张表；条件触发项移出。

**团队保留的两条风险**（请知悉，不阻塞执行）：① **付费意愿仍未验证**（融资故事里请带上验证里程碑）；② **等保/备案/拟人化评估是外部审批**，务必阶段 0 并行。
