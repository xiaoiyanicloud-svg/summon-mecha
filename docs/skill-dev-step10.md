## 关键行为

- 支付回调仅将 pending/pending_payment 推进到 processing。取消、关闭、风控订单收到迟到成功回调时，保留支付流水并生成待核查告警，不重新交付，也不自行决定资金退款。
- 单条交付失败不会阻断同订单其余条目。仅明确成功可以清除技术失败；正常等待绑定、业务拒绝和技术异常使用不同原因码。
- 自动补偿只处理已有 app 授权的明确技术异常，重新检查成功支付流水、金额、订单/条目归属、当前设备、有效期、售后、退款和熔断。缺授权、Agent缺任务、配置缺失等进入巡检与人工处理。
- 初次尝试之外最多补偿3次，等待时间为60/300/900秒。`meta.delivery_retry` 是共同业务预算，队列重投、扫描、回调与 CLI 不重置次数。进程中断保留已消耗次数，租约到期后重新核验。
- 相关写入口使用一致的资源锁顺序；退款网关调用保持在本地准备事务之外。原生退款金额及授权撤销政策未改动。
- 显式 `HttpResponseException` 保留其状态、响应体和响应头；其他HTTP异常交由Laravel正常渲染，保留419/429/405与Retry-After/Allow，修复旧处理将其误改成500的问题。已知Bagisto页面与表单验证重定向维持原合同。
