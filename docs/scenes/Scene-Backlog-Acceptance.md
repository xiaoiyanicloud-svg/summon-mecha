## 1 交付规则和职责

每个工作包开工时填写实现人、复核人、前置决策、关联提交和迁移影响；关闭时必须附测试环境、命令/结果、接口或页面证据、回退方法及运营签收。每个有用户可见行为的任务同时覆盖入口、API、后台及数据流，不以“页面画完”“返回 200”“新增表成功”作为完成。

| 职责 | 必须签收的内容 |
|---|---|
| 产品/业务负责人 | 服务包范围、价格单位、商务条件、取消/损坏/验收规则和承诺用语 |
| 方案工程师/交付运营 | 能力证据、现场 schema、实物资源、工作日历、任务和验收标准 |
| 架构/后端/DB | 不变式、状态、约束、事务、API/错误码、老接口兼容、迁移与恢复 |
| 前端/设计 | Options API、H5/小程序、基础状态、直接链接、可访问性和版本冲突体验 |
| QA/安全 | 独立 MySQL、并发进程、权限、状态矩阵、故障注入和回归证据 |
| 运维 | 运行拓扑、队列/scheduler、告警、停写、恢复、备份和生产承接 |

这些是职责要求，不声称当前已有这些人员或已完成审阅。一个人兼任时仍保留独立复核和批准记录；临时简化不得省略关键验收。

## 10 测试环境和上线证据要求

测试库必须独立命名并在 bootstrap 断言：APP_ENV=testing、数据库名属于允许列表且与业务库不同、无生产外部凭证、邮件/短信/支付/设备命令使用隔离实现。不满足立即退出，禁止 RefreshDatabase 指向当前业务库。

MySQL 并发测试使用两个真实连接/进程和同步屏障，记录锁获取、等待、提交顺序及实际记录；单进程顺序调用和 SQLite 不证明 MySQL 锁语义。SC3-05 尤其要覆盖 Bagisto 监听器创建授权/库存操作的事务与副作用，不只 mock OrderRepository 返回对象。

每次上线包必须包含：

- 本包任务 ID、提交哈希、触及路径、迁移/回填前后统计和未解决项。
- `php -l`、前端编译、目标路由及权限、独立测试库用例和运行环境；不能用 Node VM 代替小程序编译。
- H5 和小程序关键页面与错误分支证据，包含真实需求号及可遮罩查询结果。
- worker/scheduler 正在运行和故障恢复的证据、告警负责人、开关值及回退步骤。
- 一笔正常及一笔异常业务从需求到验收/整改的关联对象清单；验证事实来源与历史快照。
